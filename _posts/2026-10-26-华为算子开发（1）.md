# 将华为 CANN 9.2.0 优雅搬上 Arch Linux：AUR 拆包实践与 Ascend C 算子初体验

> **作者按**：在 Arch Linux 上折腾华为昇腾（Ascend）CANN 开发环境可不是一件轻松的事。官方给出的往往是一个几 GB 的巨型 `.run` 安装包，一股脑往 `/opt/ascend` 里砸。为了让这套工业级大部头能像普通的开源软件一样用 `pacman` / `yay` 顺畅管理，我花了一番心思把它拆解成了一组符合 AUR 规范的包。
>
> 本文将带你看看这套 AUR 包是怎么设计的、**为什么要这么大费周章地拆包**，以及如何在无 NPU 的普通 x86 机器上，用模拟器跑通你的第一个 Ascend C 算子。

## 为什么要拆包？——巨型 Toolkit 的“解耦艺术”

拿到华为的 CANN 官方安装包时，最直观的感受就是“大而全”。官方的做法通常是提供一个巨大的 `toolkit` 包，把运行时、编译器、调试工具、各种套件全塞在里面。

但在 Arch Linux（以及现代 Linux 发行版）的包管理哲学中，这种“巨石型（Monolithic）”安装方式存在几个明显的痛点：

1. **体积与依赖臃肿**：并不是每个开发者都需要 AMCT 量化工具或 NNAL 算子库。如果只想写个简单的 Ascend C 算子，却得被迫安装好几个 GB 的全套组件，很不环保。
2. **源码构建（`-git`）与二进制（`-bin`）的权衡**：官方二进制体积巨大，而部分核心组件（如 Runtime 和 Devkit）如果能从源码编译，不仅能更好地适配本地工具链，还能带来更干净的定制空间。
3. **互斥与多版本共存**：AUR 讲究“各司其职”。将 `-git` 和 `-bin` 做成互斥备选（通过 `provides`/`conflicts`），可以让喜欢追新、跟代码的极客去编 `-git`，而想要快速复现环境的工程人员直接用 `-bin` 一键拉取。

基于这些考量，我把 CANN 9.2.0 进行了精细化解耦，形成了清晰的**包职责与依赖链**：

| **拆分包名**                    | **类型**      | **拆分技术考虑**                                             |
| ------------------------------- | ------------- | ------------------------------------------------------------ |
| `asc-runtime-git` / `-bin`      | 源码 / 二进制 | **核心基石**。包含 ACL、GE 客户端、HCCL 和 `set_env.sh`。它是所有上层应用和设备通信的底层桥梁。 |
| `asc-devkit-git` / `-bin`       | 源码 / 二进制 | **开发套件**。剥离了运行时的纯开发依赖（tikcpp、头文件、设备库），便于轻量化分发。 |
| `asc-tools-git` / `-bin`        | 源码 / 二进制 | **独立工具**。包含 `cpudebug`、`msobjdump`、算子工程模板等。很多人容易把它和 toolkit 混淆，其实它是独立的调试与脚手架组件。 |
| `asc-bisheng-bin`               | 官方二进制    | **编译器独立**。将毕昇编译器（`bisheng`、`hcc`、`ccec_compiler`）独立打包。因为编译器版本对源码构建（`-git` 包）至关重要，独立出来可以保证工具链的纯净与优先就绪。 |
| `asc-toolkit-bin`               | 官方二进制    | **封闭组件聚合**。官方 toolkit 扣掉 runtime、devkit、tools 和 bisheng 后，剩下的“封闭组件”（GE、metadef、AOE、simulator、pyACL 等）收归于此。 |
| `asc-amct-bin` / `asc-nnal-bin` | 官方二进制    | **垂直领域扩展**。量化工具（AMCT）和加速库（NNAL/ATB）作为可选增值包，按需安装，绝不污染基础环境。 |

>[!NOTE]
>
>注意 asc-toolkit-bin还有很多包没有拆分出来，并且当前我暂时没有很多精力去维护这个aur。如果有志愿的，可以帮我去把asc-toolkit-bin的.run文件更进一步拆分，以及收养这些包。

通过这样的依赖链串联（例如 `asc-tools` → `asc-devkit` → `asc-bisheng` + `asc-runtime`），你既可以实现极简的按需安装，也能享受到类 pacman 生态的模块化管理快感。

## 1. 用 `yay` 一条命令装好整套环境

### 1.1 准备 yay

如果你还没装 `yay`，可以先快速构建一个：

Bash

```
sudo pacman -S --needed base-devel git
git clone https://aur.archlinux.org/yay.git /tmp/yay
cd /tmp/yay && makepkg -si
```

### 1.2 一条命令安装完整开发环境

如果你想体验源码构建的乐趣（runtime/devkit/tools 走本地构建，其余用官方二进制封闭组件），可以直接运行：

Bash

```
yay -S --needed asc-runtime-git asc-devkit-git asc-tools-git \
                asc-toolkit-bin asc-bisheng-bin asc-amct-bin asc-nnal-bin
```

> **注意**：`-git` 与 `-bin` 声明了同名 `provides`/`conflicts`，**切勿**在同一次事务中混装，`yay` 会拒绝这种冲突。

关于架构支持：所有的 PKGBUILD 均已声明 `arch=('x86_64' 'aarch64')`。在 ARM64（aarch64）机器上，可以直接 `yay -S ...` 享受原生编译或二进制适配，无需手动修改脚本。

### 1.3 环境变量自动生效（告别手动 source）

传统 CANN 安装极其折腾的一点就是每次都要 `source /opt/ascend/cann-9.2.0/set_env.sh`。这套 AUR 包在系统层做好了原生适配：

- **Bash / Zsh**：通过 `/etc/profile.d/ascend-cann.sh` 自动加载。
- **Fish**：提供原生 `/etc/fish/conf.d/ascend-cann.fish` 配置，完美接管 `PATH`、`LD_LIBRARY_PATH`、`PYTHONPATH`、`ASCEND_HOME_PATH` 等核心环境变量。

新开一个终端，直接验证：

Bash

```
command -v bisheng        # 应该输出 /opt/ascend/cann-9.2.0/bin/bisheng
echo $ASCEND_HOME_PATH    # 应该输出 /opt/ascend/cann-9.2.0
```

## 2. 第一个算子：无 NPU 机器上的 Ascend C 逐元素乘法

即使手头没有华为昇腾昇腾硬件（NPU），我们也可以借助 CANN 强大的**CPU 模拟器模式**（`sim`）来完成 Ascend C 算子的编写、编译与自测。

### 2.1 编写算子代码 (`mul.asc`)

新建一个 `mul_op` 目录，并创建 `mul.asc`。我们将 kernel、host 侧调用以及结果对拍写在同一个编译单元里：

```
/* !
 * \file mul.asc
 * \brief Element-wise multiply operator, Ascend C single-file sample.
 *        Kernel + host + verification in one translation unit.
 */

#include <cstdint>
#include <vector>
#include <algorithm>
#include <iterator>
#include <iostream>

#include "acl/acl.h"
#include "kernel_operator.h"

template <uint32_t blockLength>
__vector__ __global__ void mul_custom(__gm__ float* x, __gm__ float* y, __gm__ float* z)
{
    AscendC::InitSocState();

    AscendC::GlobalTensor<float> xGm, yGm, zGm;
    xGm.SetGlobalBuffer(x + block_idx * blockLength, blockLength);
    yGm.SetGlobalBuffer(y + block_idx * blockLength, blockLength);
    zGm.SetGlobalBuffer(z + block_idx * blockLength, blockLength);

    AscendC::LocalMemAllocator<AscendC::Hardware::UB> ubAllocator;
    AscendC::LocalTensor<float> xLocal = ubAllocator.Alloc<float, blockLength>();
    AscendC::LocalTensor<float> yLocal = ubAllocator.Alloc<float, blockLength>();
    AscendC::LocalTensor<float> zLocal = ubAllocator.Alloc<float, blockLength>();

    AscendC::DataCopy(xLocal, xGm, blockLength);
    AscendC::DataCopy(yLocal, yGm, blockLength);
    AscendC::PipeBarrier<PIPE_ALL>();

    AscendC::Mul(zLocal, xLocal, yLocal, blockLength);
    AscendC::PipeBarrier<PIPE_ALL>();

    AscendC::DataCopy(zGm, zLocal, blockLength);
    AscendC::PipeBarrier<PIPE_ALL>();
}

std::vector<float> kernel_mul(std::vector<float>& x, std::vector<float>& y)
{
    constexpr uint32_t numBlocks = 8;
    constexpr uint32_t blockLength = 2048;
    uint32_t totalLength = x.size();
    size_t totalByteSize = totalLength * sizeof(float);
    float* xDevice = nullptr;
    float* yDevice = nullptr;
    float* zDevice = nullptr;
    uint8_t* zHost = nullptr;

    aclInit(nullptr);
    int32_t deviceId = 0;
    aclrtSetDevice(deviceId);
    aclrtStream stream = nullptr;
    aclrtCreateStream(&stream);

    aclrtMalloc((void**)&xDevice, totalByteSize, ACL_MEM_MALLOC_HUGE_FIRST);
    aclrtMalloc((void**)&yDevice, totalByteSize, ACL_MEM_MALLOC_HUGE_FIRST);
    aclrtMalloc((void**)&zDevice, totalByteSize, ACL_MEM_MALLOC_HUGE_FIRST);
    aclrtMallocHost((void**)&zHost, totalByteSize);

    aclrtMemcpy(xDevice, totalByteSize, x.data(), totalByteSize, ACL_MEMCPY_HOST_TO_DEVICE);
    aclrtMemcpy(yDevice, totalByteSize, y.data(), totalByteSize, ACL_MEMCPY_HOST_TO_DEVICE);

    mul_custom<blockLength><<<numBlocks, 0, stream>>>(xDevice, yDevice, zDevice);
    aclrtSynchronizeStream(stream);

    aclrtMemcpy(zHost, totalByteSize, zDevice, totalByteSize, ACL_MEMCPY_DEVICE_TO_HOST);
    std::vector<float> z((float*)zHost, (float*)(zHost + totalByteSize));

    aclrtFree(xDevice);
    aclrtFree(yDevice);
    aclrtFree(zDevice);
    aclrtFreeHost(zHost);

    aclrtDestroyStream(stream);
    aclrtResetDevice(deviceId);
    aclFinalize();

    return z;
}

uint32_t VerifyResult(std::vector<float>& output, std::vector<float>& golden)
{
    auto printTensor = [](std::vector<float>& tensor, const char* name) {
        constexpr size_t maxPrintSize = 20;
        std::cout << name << ": ";
        std::copy(
            tensor.begin(), tensor.begin() + std::min(tensor.size(), maxPrintSize),
            std::ostream_iterator<float>(std::cout, " "));
        if (tensor.size() > maxPrintSize) {
            std::cout << "...";
        }
        std::cout << std::endl;
    };
    printTensor(output, "Output");
    printTensor(golden, "Golden");
    
    bool ok = output.size() == golden.size();
    for (size_t i = 0; ok && i < golden.size(); ++i) {
        ok = std::abs(output[i] - golden[i]) <= 1e-4f * std::max(1.0f, std::abs(golden[i]));
    }
    if (ok) {
        std::cout << "test pass!" << std::endl;
        return 0;
    } else {
        std::cout << "test failed!" << std::endl;
        return 1;
    }
}

int32_t main(int32_t argc, char* argv[])
{
    constexpr uint32_t totalLength = 8 * 2048;
    std::vector<float> x(totalLength);
    std::vector<float> y(totalLength);

    for (uint32_t i = 0; i < totalLength; ++i) {
        x[i] = i * 0.1f;
        y[i] = (i % 7) * 0.25f + 0.5f;
    }

    std::vector<float> output = kernel_mul(x, y);

    std::vector<float> golden(totalLength);
    for (uint32_t i = 0; i < totalLength; ++i) {
        golden[i] = x[i] * y[i];
    }

    return VerifyResult(output, golden);
}
```

### 2.2 编写 `CMakeLists.txt`

```
cmake_minimum_required(VERSION 3.16)

set(CMAKE_ASC_ARCHITECTURES "dav-2201" CACHE STRING "NPU architecture: dav-2201, dav-3510")

find_package(ASC REQUIRED)

project(mul_op LANGUAGES ASC CXX)

add_executable(demo
    mul.asc
)

target_compile_options(demo PRIVATE
    $<$<COMPILE_LANGUAGE:ASC>:--npu-arch=${CMAKE_ASC_ARCHITECTURES}>
)
```

### 2.3 编译与模拟器运行

由于 Arch Linux 的滚动更新特性，GCC 版本可能比较超前（例如 GCC 16），而毕昇编译器底层基于相对传统的 Clang，可能会对最新的 `libstdc++` 头文件水土不服。我们可以通过 `CMAKE_ASC_FLAGS` 临时指定兼容头文件路径：

```
cmake -S . -B build \
  -DCMAKE_ASC_RUN_MODE=sim \
  -DCMAKE_ASC_ARCHITECTURES=dav-2201 \
  -DCMAKE_ASC_FLAGS="-nostdinc++ \
    -isystem /usr/lib/gcc/x86_64-pc-linux-gnu/15.3.0/include/c++ \
    -isystem /usr/lib/gcc/x86_64-pc-linux-gnu/15.3.0/include/c++/x86_64-pc-linux-gnu \
    -lstdc++ -D__clang_major__=3 -D__clang_minor__=0"
```

开始编译并运行：

```
cmake --build build -j"$(nproc)"
./build/demo
```

见证奇迹的时刻，终端输出：

```

Output: 0 0.075 0.2 0.375 0.6 0.875 1.2 0.35 ...
Golden: 0 0.075 0.2 0.375 0.6 0.875 1.2 0.35 ...

```

看到 `test pass!`，说明即使手头没有华为昇腾硬件，我们照样能在 Arch Linux 上通过 AUR 环境和模拟器把 Ascend C 算子玩得转。
